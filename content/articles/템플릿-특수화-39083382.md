입별로 옵션 값을 다르게 주는 템플릿 특수화에 대해 알아보자\~

---

```javascript
template<typename T>
struct TTraits
{
    enum { bEnabled = false };
};

struct FMyType
{
    void Execute() {}
};

template<>
struct TTraits<FMyType>
{
    enum { bEnabled = true };
};
```

이게 뭔데!!!!!!!!!!!!!!!!

이게 핵심이다.<br />어떤 타입 T가 들어오든 기본적으로 TTraits\<T>::bEnabled false이다.

```javascript
template<typename T>
struct TTraits
{
    enum { bEnabled = false };
};
```

이럼 내가 MyType에 대해서만 예외적인 규칙을 만든셈이다.

```javascript
template<>
struct TTraits<FMyType>
{
    enum { bEnabled = true };
};
```

즉

```javascript
// 기본값
TTraits<int>::bEnabled      // false
TTraits<float>::bEnabled    // false

// FMyType만 따로 특수화됨
TTraits<FMyType>::bEnabled  // true
```

이렇게 된다고 보면 된다.

요즘c++로는

```javascript
template<typename T>
struct TTraits
{
    static constexpr bool bEnabled = false;
};

struct FMyType
{
    void Execute() {}
};

template<>
struct TTraits<FMyType>
{
    static constexpr bool bEnabled = true;
};
```

이렇게 쓰고

사용은 이렇게 한다고 한다.

```javascript
if constexpr (TTraits<FMyType>::bEnabled)
{
    // FMyType일 때만 컴파일됨
}
```

# 왜 굳이 이렇게 하냐?

```javascript
if (bEnabled)
{
    Value.Execute();
}
```

런타임에서 이런 식으로 하면 문제가 있음.

<code>bEnabled == false</code>여도 컴파일러는 기본적으로 <code>Value.Execute()</code>가 문법적으로 가능한지 확인하려고 함.

예를 들어

```javascript
int Value = 10;

if (false)
{
    Value.Execute(); // int에는 Execute 없음 → 컴파일 에러
}
```

이런건 말이 안되겠지?

만약 이런 구조를 만들었다면??

```javascript
template<>
struct TTraits<int>
{
    enum { bEnabled = true };
};


template<typename T>
void TryExecute(T& Value)
{
    if constexpr (TTraits<T>::bEnabled)
    {
        Value.Execute();
    }
}
```

TryExecute\<int>(5) 이렇게 했을때 true를 반환할수 있다는거야
