아무 클래스에 아래처럼 커스텀 로그를 선언매크로를 쓴다.

```c++
DECLARE_LOG_CATEGORY_EXTERN(LogLC, Log, All);
```

커스텀 로그매크로는 펼쳐보면 이렇게 생겼다.

```c++
extern struct FLogCategoryLogLC : public FLogCategory<ELogVerbosity::Log, ELogVerbosity::All> {
    __forceinline FLogCategoryLogLC() : FLogCategory(L"LogLC") {
    }
} LogLC;
```

cpp로 넘어와서 커스텀 매크로를 정의하는 매크로를 호출한다.

```c++
DEFINE_LOG_CATEGORY(LogLC);
```

저 매크로도 펼쳐보면 그냥 선언한것이다

```c++
FLogCategoryLogLC LogLC;
```

<b>로깅</b>

현재 Overwatch 로깅은 단순 <code>UE_LOG</code> 래핑에서 한 단계 더 나아가서, 네트워크/액터/오브젝트 문맥을 같이 찍을 수 있게 되어있다.

```c++
OVERWATCH_API DECLARE_LOG_CATEGORY_EXTERN(LogOW, Log, All);
OVERWATCH_API DECLARE_LOG_CATEGORY_EXTERN(LogOWCore, Log, All);
OVERWATCH_API DECLARE_LOG_CATEGORY_EXTERN(LogOWGame, Log, All);
OVERWATCH_API DECLARE_LOG_CATEGORY_EXTERN(LogOWUI, Log, All);
OVERWATCH_API DECLARE_LOG_CATEGORY_EXTERN(LogOWAbilitySystem, Log, All);
OVERWATCH_API DECLARE_LOG_CATEGORY_EXTERN(LogOWNetwork, Log, All);
```

```c++
#define OW_LOG(InCategory, InVerbosity, Format, ...) UE_LOG(InCategory, InVerbosity, TEXT("[%s] " Format), ANSI_TO_TCHAR(__FUNCTION__), ##__VA_ARGS__)
#define OW_NET_LOG(InCategory, InVerbosity, InWorldContextObject, Format, ...) UE_LOG(InCategory, InVerbosity, TEXT("[%s][%s] " Format), ANSI_TO_TCHAR(__FUNCTION__), *FOWLog::BuildWorldContextString(InWorldContextObject), ##__VA_ARGS__)
```

<code>OW_LOG</code>는 함수명을 자동으로 앞에 붙여주고, <code>OW_NET_LOG</code>, <code>OW_ACTOR_LOG</code>는 World/NetMode/Role까지 붙일 수 있다.

멀티플레이 디버깅에서는 "서버에서 찍힌건지, 클라에서 찍힌건지"가 절반 이상이라 이게 중요하다.

왜 이렇게 하냐

→ Lyra식 초기화는 GameMode, GameStateComponent, PlayerState, PawnComponent, LocalPlayerSubsystem이 서로 다른 타이밍에 움직인다. 로그에 NetMode와 Role이 없으면 같은 함수가 여러 월드에서 찍힌 것처럼 보여서 흐름 파악이 힘들어진다.
