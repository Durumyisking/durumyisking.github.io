람다표현식, 람다 함수, 익명함수 등으로 불리는 lamda에 대해 배워보자

---

<b>람다는 이름은 없지만 고유한 객체로써 작동한다.</b>

<b>람다는 함수객체와 함수포인터의 장점만을 가지고있다.</b>

<blockquote>

<b>함수 객체와는 다르게 class를 선언할 필요가 없다.</b>

⇒코드의 길이가 줄어든다.

<b>함수 포인터와 다르게 인라인화가 가능하다.</b>

</blockquote>

아래는 일반함수와 람다함수의 문법이다.

```c++
// 일반 함수 정의
void sum1(int a, int b)
{
    cout << "sum1 func : " << a + b << endl;
}
 
int main(void) {
 
    //일반 함수 호출
    sum1(10, 20);
 
    //람다 함수
    [](int a, int b)
    {
        cout << "sum2 lambda : " << a + b << endl;
    }(30, 40);
 
    return 0;
}
```

<aside class="callout">

<b>일반적인 함수 호출</b>

반환형 함수이름 (매개변수)

\{

// 함수동작

\}

</aside>

잘 알고있는 일반 함수 호출에 비해 람다는 상이한 문법을 가지고있다.

<details>
<summary><b>람다의 기본 구조 및 문법</b></summary>

<b>\[\] ( ) \{  \} ( )\[캡처\] (매개변수) \{ 함수 동작 \} (호출인자)</b>

첫 번째 \[\] : 캡처

두 번째 () : 매개변수 선언 부분 (생략 가능 - 매개변수 필요 없을 때)

세 번째 \{\} : 함수 동작 부분

네 번째 <b>() :</b> 함수 호출 시 인자 (생략 가능 - 호출 시에만 사용)

<aside class="callout">

<b>람다 함수 생성 및 호출</b>

<b>생성</b>

\[\] (매개변수) \{ // 함수 동작 \} ;

\[\](int a, intb) \{return a + b\};

<b>호출 (구현부 뒤의 ()는 함수의 호출을 의미한다)</b>

\[\] (매개변수) \{ // 함수 동작 \} (호출 시 인자) ;

\[\](int a, intb) \{return a + b\} (10, 20);

</aside>

<b>매개변수에 따른 람다식 구분</b>

```c++
매개변수 없는 람다 표현식 : [] { cout << " 인자 없음 " << endl; };

매개변수 있는 람다 표현식 : [] (int a, int b, int c) { cout << a << b << c << endl; };

매개변수 없고 반환 있는 람다 : [] { return 200; };

매개변수 있고 반환 있는 람다 : [] (int a, int b) { return a * b; } ;
```

<details>
<summary><b>캡처 \[\]</b></summary>

- 캡처는 람다 외부에 정의되어있는 변수나 상수를 람다 내부에서 사용하기 위해서 사용한다.
- <b>캡처의 2가지 방법</b>
  - Call by Value - 복사
  - Call by Reference - 참조

  뭐 특별한게 있는건 아니고 아래 코드로 설명한다.

  ```c++
  int Value1 = 1;
  int Value2 = 2;
  int Value3 = 3;
  int Value4 = 4;

  // 복사
  [Value1 , Value2 ] { 
          cout << "result1, result2 : " << result1 << ", " << result2 << endl;
          // 복사한 변수에는 대입 불가능
          // Value1 = a + b; 
          // Value2 = 99999;
  };

  // 참조
  [&Value3 , &Value4 ](int a, int b) {
          result3 = 22222;
          result4 = a + b;
  				// 참조한 변수에는 대입 가능

      }(10, 20);
  ```

- <b>전체 복사/참조</b>
  외부에서 모든 값을 사용하고 싶을 수 있다.

  그때 일일히 \[v1, v2 v3, …. v1000\] 할 수는 없으니까 <b>전체 복사/참조 문법</b>을 사용한다.

  ```c++
  // 전체 복사
  [=]
      {
          cout << "result1, 2 : " << result1 << ", " << result2 << endl;
          cout << "result3, 4 : " << result3 << ", " << result4 << endl;
      };

  // 전체 참조
  [&]
       {
           cout << "result1, 2 : " << result1 << ", " << result2 << endl;
           cout << "result3, 4 : " << result3 << ", " << result4 << endl;
       };

  ```
- <b>참조, 복사</b> <b>복합사용</b>
  ```c++
  // 전체 복사, 일부 참조
  [=, &result3, &result4](int x)
      {
          cout << "result1, 2 : " << result1 << ", " << result2 << endl;
          cout << "result3, 4 : " << result3 << ", " << result4 << endl;
          cout << "매개변수 : " << x << endl;
   
          result3 += x; // 일부 참조
          result4 += x; // 일부 참조
      }(30);

   // 전체 참조, 일부 복사
   [&, result1, result2](int y)
  		 {
  		     cout << "result1, 2 : " << result1 << ", " << result2 << endl;
  		     cout << "result3, 4 : " << result3 << ", " << result4 << endl;
  		     cout << "매개변수 : " << y << endl;
  		
  		     result3 += y; // 전체 참조
  		     result4 += y; // 전체 참조
  		 }(99);
  ```
- <b>캡처 초기화 (복사)</b>
  ```c++
  int x = 10;
  [=, newX = x + 1]
      {
          cout << "newX : " << newX<< ", " << newX << endl;
          cout << "X : " << x << ", " << x<< endl;
      };
  => newX : 11, X : 10
  ```

  이런 문법을 사용하여 <b><code>newX</code></b>를 캡처 단계에서 초기화시킬수 있다.

  람다에서 생성된 변수는 해당 람다를 감싸고 있는 코드블록 탈출 전까지 사라지지 않는다.

  <b>캡처 블록에서 초기화된 변수는 </b><b><span>const</span></b><b>로 선언이 된다.</b>

- <b>Mutable</b>
  ```c++
  int x = 10;
  [=, newX = x + 1]()
      {
  			x = 12 // 불가능!
      };

  ```

  우리는 위 코드에서 x = 12 이런 코드 작성 못한다

  그래서 mutable이라는 키워드가 있다.

  ```c++
  int x = 10;
  [=, newX = x + 1] () mutable
      {
  				x = 12; // 가능
      };

  ```

- <b>캡처 초기화 (참조)</b>
  ```c++
  int x = 10;

  auto l1 = [&](){
      x = 5;
      return x;
  };

  auto l2 = [&, newX = x + 100](){
      return newX ;   
  };

  cout << l1() << endl;
  cout << "main  x  : " << x << endl;;
  cout << l2() << endl;
  cout << "main  x  : " << x << endl;;
  => 5, 5, 110, 5
  ```

  초기화 하는 부분은 위의 복사 초기화와 크게 다를게 없다.

  하지만 <b><code>l2</code></b> 의 결과가 이상한 것을 알 수 있다.

  위에서 x가 5인게 나왔는데 newX = x + 100의 결과로 110이 나온다.

  <b>이는 람다의 객체화가 컴파일 단계에서 일어나기 때문에 벌어지는 현상이다.</b>

  따라서 람다 표현식에서 사용하는 <b><code>x</code></b> 값은 람다 객체가 생성될 당시의 <b><code>x</code></b> <b>값(10)</b>이 그대로 유지된다.

</details>

### <b>그럼 이거 왜 써요?</b>

<details>
<summary><b>auto 자료형과 찰떡궁합이다.</b>.</summary>

<aside class="callout">

람다 함수의 정의를 auto로 선언한 변수에 저장할 수 있다.                                          <b>auto func1 = \[\] (int a, int b) \{ return a \* b \};</b>

</aside>

이렇게 저장해두면 실 사용할 때 func1(10, 30) 이런식으로 사용이 가능하다.

<details>
<summary><b>함수의 인자로도 사용이 가능하다</b></summary>

즉 함수 포인터로써의 역할을 한다는 말이다.

```c++
// 기존 사용
void compare(int a, int b) { return a > b; }
std::array<int, 10> arr1 = { 5, 4, 2, 1, 100, 32, 2, 4, 6, 9 };
sort( arr31.begin(), arr1.end(), [](int a, int b) {return a > b; } );

// 람다 사용
std::array<int, 10> arr2 = { 5, 4, 2, 1, 100, 32, 2, 4, 6, 9 };
sort( arr2.begin(), arr2.end(), [](int a, int b) {return a > b; } );
```

</details>

<details>
<summary><b>컴파일러의 자동 인라인</b></summary>

함수의 인자로 람다를 사용하면 컴파일러가 자동으로 인라인화 시켜준다.

<b><span>함수 포인터는 함수의 인라인화가 불가능하다는 단점</span></b>이 있는데

<b><span>람다는 특정상황들을 제외하고는 인라인화가 가능</span></b>하다.

- <b>람다가 인라인이 가능한 경우 및 이유</b>
  ```c++
  auto f1 = [](int a, int b) {
          return a + b;
      };
  ```

  다시 말하지만 람다는 이름이 없는 고유 객체이다.

  프로그래머는 람다의 이름과 어떤 타입으로 정의 되었는지 알 수 없지만 \*<b>컴파일 과정\*에서 람다라는 객체를 생성</b>한다는 말이다.

  <b>컴파일러가 인라인하는 기준은 명확하게 명시되어 있는 함수만을 인라인(치환) 한다.</b>

- <b>람다가 인라인이 불가능한 경우 및 이유</b>
  ```c++
  int(*f2)(int, int) = [](int a, int b) {            
          return a + b;
    };

  std::function<int(int, int)> f3 = [](int a, int b) {   
      return a + b;
  	};
  ```

  <b>람다 함수는 함수 객체를 생성한다.</b>

  위 두 가지 상황은 함수 객체를 함수 포인터로 변환하고 있기 때문에 컴파일러는 

  해당 람다 함수를 인라인화 할 수 없다.

  <b>함수 포인터가 가리키는 함수는 런타임 단계에서 결정</b>되기 때문에 <b>컴파일 과정에서 일어나는 인라인화</b>가 일어나지 않는다.

</details>
