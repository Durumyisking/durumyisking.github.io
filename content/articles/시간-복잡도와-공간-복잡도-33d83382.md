# 개요

<b><span>시간복잡도</span></b>와 <b><span>공간복잡도</span></b>는 입력 크기가 커질수록 알고리즘이 <b><span>얼마나 느려지고</span></b>, <b><span>얼마나 많은 메모리</span></b>를 쓰는지를 표현하는 기준

## <b>1. 기본 용어 정리</b>

### <b>알고리즘</b>

문제를 해결하는 절차입니다.

### <b>입력 크기 n</b>

복잡도를 계산할 때 기준이 되는 값입니다.

예:

- 배열 길이
- 문자열 길이
- 노드 개수
- 간선 개수

### <b>연산 횟수</b>

알고리즘이 수행하는 핵심 작업 수입니다.

예:

- 비교 횟수
- 대입 횟수
- 반복문 실행 횟수

정확한 초/밀리초보다 이런 연산 수 증가를 먼저 봅니다.

---

## <b>2. 시간복잡도란</b>

시간복잡도는 입력 크기 n이 커질 때 실행 시간이 어떻게 증가하는지를 나타냅니다.

예를 들어:

<pre><code>for (int i = 0; i &lt; n; ++i)
{
    Sum += Arr[i];
}</code></pre>

이 코드는 원소를 n개 한 번씩 보므로 시간복잡도는 보통 O(n)입니다.

### <b>왜 중요한가</b>

입력이 작을 때는 다 비슷해 보여도, 입력이 커지면 차이가 매우 커집니다.

예:

- O(n)은 100만 개여도 가능할 수 있음
- O(n\^2)은 100만 개면 사실상 불가능한 경우가 많음

---

## <b>3. 공간복잡도란</b>

공간복잡도는 알고리즘이 사용하는 메모리 양이 입력 크기에 따라 어떻게 증가하는지 나타냅니다.

예:

<code>vector&lt;int&gt; Copy = Arr;</code>

배열 전체를 복사하면 입력 크기만큼 추가 메모리가 필요하므로 보통 O(n) 추가 공간이 듭니다.

### <b>공간복잡도에서 자주 보는 구분</b>

- 전체 공간: 입력 자체까지 포함
- 보조 공간(Auxiliary Space): 입력 외에 알고리즘이 추가로 쓰는 메모리

실전에서는 보통 추가로 얼마나 더 쓰는지를 많이 봅니다.

---

## <b>4. 점근적 표기법</b>

### <b>Big-O 표기법: O(...)</b>

상한을 나타냅니다.

보통 “최악의 경우 기준으로 이 정도로 증가한다”고 이해하면 됩니다.

예:

- O(1) 상수 시간
- O(log n) 로그 시간
- O(n) 선형 시간
- O(n log n) 준선형
- O(n\^2) 제곱 시간

### <b>Big-Omega 표기법: Ω(...)</b>

하한을 나타냅니다.

적어도 이 정도는 걸린다는 뜻입니다.

### <b>Big-Theta 표기법: Θ(...)</b>

상한과 하한이 같은 경우입니다.

즉, 증가율이 정확히 그 정도라고 볼 수 있습니다.

### <b>공부 초반에는 이렇게 이해하시면 충분합니다</b>

- 가장 많이 쓰는 것은 O(...)
- 문제 풀이에서는 거의 항상 시간복잡도 = O(...) 형태로 말함

---

## <b>5. 자주 나오는 복잡도 순서</b>

빠른 것부터 느린 것 순서입니다.

<code>O(1) &lt; O(log n) &lt; O(n) &lt; O(n log n) &lt; O(n^2) &lt; O(n^3) &lt; O(2^n) &lt; O(n!)</code>

### <b>각각의 느낌</b>

- O(1): 입력 크기와 무관
- O(log n): 매우 효율적
- O(n): 입력 한 번 순회
- O(n log n): 정렬류에서 자주 나옴
- O(n\^2): 이중 반복문
- O(2\^n), O(n!): 완전탐색, 조합 폭발

---

## <b>6. 시간복잡도 계산 기본 규칙</b>

### <b>1. 상수는 무시</b>

O(2n)은 O(n)으로 씁니다.

이유:

입력이 커질수록 2배 같은 상수보다 n 자체의 증가가 더 중요하기 때문입니다.

### <b>2. 낮은 차수는 무시</b>

O(n\^2 + n + 1)은 O(n\^2)입니다.

### <b>3. 순차 실행은 더함</b>

<pre><code>for (...) { ... }   // O(n)
for (...) { ... }   // O(n)</code></pre>

전체는 O(n + n) = O(n)입니다.

### <b>4. 중첩 반복은 곱함</b>

<pre><code>for (int i = 0; i &lt; n; ++i)
{
    for (int j = 0; j &lt; n; ++j)
    {
        ...
    }
}</code></pre>

전체는 O(n\^2)입니다.

### <b>5. 입력이 다른 두 개면 변수도 나눠서 봄</b>

<pre><code>for (int i = 0; i &lt; n; ++i) { ... }
for (int j = 0; j &lt; m; ++j) { ... }</code></pre>

전체는 O(n + m)입니다.

무조건 O(n)으로 뭉개면 안 됩니다.

---

## <b>7. 공간복잡도 계산 기본 규칙</b>

### <b>O(1) 공간</b>

추가 변수 몇 개만 쓰는 경우

<pre><code>int Sum = 0;
int MaxValue = 0;</code></pre>

입력이 커져도 변수 개수는 늘지 않으므로 O(1)입니다.

### <b>O(n) 공간</b>

입력 크기만큼 추가 저장

<code>vector&lt;int&gt; Temp(n);</code>

### <b>재귀도 공간을 씁니다</b>

재귀 호출은 호출 스택을 사용하므로 깊이에 따라 공간이 듭니다.

예:

- 깊이 n 재귀면 보통 O(n) 스택 공간

---

## <b>8. 예제로 보는 감각</b>

### <b>예제 1: 배열 합 구하기</b>

<pre><code>int Sum = 0;
for (int i = 0; i &lt; n; ++i)
{
    Sum += Arr[i];
}</code></pre>

- 시간복잡도: O(n)
- 공간복잡도: O(1)

### <b>예제 2: 모든 쌍 비교</b>

<pre><code>for (int i = 0; i &lt; n; ++i)
{
    for (int j = 0; j &lt; n; ++j)
    {
        ...
    }
}</code></pre>

- 시간복잡도: O(n\^2)
- 공간복잡도: O(1)

### <b>예제 3: 이진 탐색</b>

정렬된 배열에서 중간값 기준으로 반씩 버립니다.

- 시간복잡도: O(log n)
- 공간복잡도:
  - 반복문 구현: O(1)
  - 재귀 구현: O(log n)

### <b>예제 4: 병합 정렬</b>

- 시간복잡도: O(n log n)
- 공간복잡도: O(n) 추가 배열 필요

---

## <b>9. 최선, 평균, 최악 경우</b>

같은 알고리즘도 경우에 따라 다를 수 있습니다.

예: 선형 탐색

- 최선: 첫 번째에서 찾음 → O(1)
- 최악: 끝까지 감 → O(n)

초반 공부에서는 보통 최악의 경우를 기준으로 봅니다.

---

## <b>10. 실전에서 자주 헷갈리는 포인트</b>

### <b>1. for문이 있다고 무조건 O(n)은 아닙니다</b>

<pre><code>for (int i = 1; i &lt; n; i *= 2)
{
    ...
}</code></pre>

이건 1, 2, 4, 8, ... 식으로 증가하므로 O(log n)입니다.

### <b>2. 재귀는 시간과 공간을 따로 봐야 합니다</b>

피보나치 단순 재귀:

- 시간복잡도: 매우 큼, 대략 O(2\^n)
- 공간복잡도: 호출 깊이만큼 O(n)

### <b>3. 컬렉션 연산도 복잡도가 있습니다</b>

예:

- 배열 인덱스 접근: 보통 O(1)
- 정렬: 보통 O(n log n)
- 해시 조회: 평균 O(1), 최악은 더 커질 수 있음

### <b>4. 입력 저장 공간과 추가 공간을 구분해야 합니다</b>

입력 배열 자체가 n개라는 사실과, 알고리즘이 추가로 n개 더 만드는 것은 다릅니다.

---

## <b>11. 왜 시간복잡도와 공간복잡도를 같이 봐야 하나</b>

둘은 종종 트레이드오프 관계입니다.

예:

- 더 빠르게 하려고 메모리를 더 쓸 수 있음
- 메모리를 아끼려면 시간이 더 걸릴 수 있음

예시:

- 해시맵 사용: 공간 증가, 시간 단축
- 제자리 정렬: 공간 절약, 구현 복잡도 증가 가능

---

## <b>12. 공부할 때 추천 순서</b>

1. O(1), O(log n), O(n), O(n\^2) 감각 익히기
2. 반복문 보고 복잡도 계산하기
3. 재귀 호출 깊이와 호출 횟수 구분하기
4. 정렬/탐색의 대표 복잡도 외우기
5. 자료구조 연산별 복잡도 정리하기
6. 문제 풀 때 “왜 이 복잡도인지” 말로 설명해보기

---

## <b>13. 아주 짧은 암기표</b>

<pre><code>시간복잡도 = 얼마나 오래 걸리는가
공간복잡도 = 얼마나 많은 메모리를 쓰는가

O(1)     상수
O(log n) 로그
O(n)     선형
O(n log n) 준선형
O(n^2)   이차
O(2^n)   지수</code></pre>

## <b>14. 처음 공부할 때의 기준 문장</b>

문제를 볼 때 이렇게 생각하시면 됩니다.

- 입력 크기 n이 무엇인지 먼저 정한다
- 핵심 연산이 몇 번 반복되는지 센다
- 추가 메모리가 입력에 비례해 늘어나는지 본다
- 상수와 낮은 차수는 버리고 가장 크게 증가하는 항만 남긴다

원하시면 답을 바로 말하지 않고,

제가 한 문제씩 채점 + 왜 그런지 설명 방식으로 같이 진행해드릴게요.

1번 n 2번 n제곱 3번 로그n

결론부터 말씀드리면, 3문제 모두 정답입니다.

간단히 이유만 바로 붙이면:

1. O(n)
   반복문이 n번 돕니다.

2. O(n\^2)
   바깥 루프 n번, 안쪽 루프 n번이므로 n \* n입니다.

3. O(log n)
   i가 1, 2, 4, 8, ...처럼 2배씩 증가하므로 반복 횟수는 log₂ n입니다. 복잡도 표기에서는 O(log n)으로 씁니다.

짧은 체크 포인트:

- 1개씩 증가하면 보통 O(n)
- 중첩으로 n번씩 돌면 O(n\^2)
- 2배씩 증가하거나 절반씩 감소하면 O(log n)

다음 연습으로 넘어가면 가장 좋은 단계는 헷갈리기 쉬운 문제입니다.

원하시면 이번엔 O(n + m), O(n log n), O(1) 섞어서 3문제 더 드리겠습니다.

## <b>문제 3</b>

<pre><code>int Value = Arr[0];
cout &lt;&lt; Value &lt;&lt; "\n";</code></pre>

질문:

- 시간복잡도는 무엇인가?

---

답은 1번, 2번, 3번 순서로 적어주시면 바로 채점해드리겠습니다.

1\. n<br />2. n제곱<br />3. 1

결론부터 말씀드리면, 1번 정답, 2번 오답, 3번 정답입니다.

1. O(n + m)
   사용자님은 n이라고 답하셨지만, 정확히는 O(n + m)입니다.

   첫 번째 반복문은 n번, 두 번째 반복문은 m번이라서 더해야 합니다.

2. O(n log n)
   이 문제는 바깥쪽이 n번, 안쪽이 1, 2, 4, 8, ...처럼 증가해서 log n번 돕니다.

   그래서 전체는:

<code>n * log n = O(n log n)</code>

O(n\^2)가 되려면 안쪽도 n번 돌아야 합니다.

1. O(1)배열 첫 원소 접근 한 번, 출력 한 번이므로 상수 시간입니다.

짧게 정리하면:

- 순서대로 따로 돌면 더하기
- 중첩 반복이면 곱하기
- 안쪽이 2배씩 증가하면 log n

정답표:

- 1번: O(n + m)
- 2번: O(n log n)
- 3번: O(1)

원하시면 다음엔 제가 조금 더 헷갈리는 문제 3개를 내고, 이번에는 공간복잡도도 같이 붙여서 연습하게 해드리겠습니다.

준선형은 어떤때 볼수있지 보통?

결론부터 말씀드리면, 준선형 O(n log n)은 보통 n개를 처리하는데 각 처리마다 log n 정도의 비용이 드는 경우나 분할정복으로 계속 반씩 나누면서 전체를 다시 합치는 경우에 자주 나옵니다.

대표적으로는 정렬에서 가장 많이 봅니다.

## <b>가장 자주 보는 경우 1: 정렬</b>

예:

- 병합 정렬
- 힙 정렬
- 퀵 정렬 평균

왜 O(n log n)이냐면:

- 데이터를 log n단계 정도로 반씩 나누고
- 각 단계에서 전체 원소 n개를 한 번씩 다루는 경우가 많기 때문입니다.

병합 정렬 감각은 이렇게 보면 됩니다.

<pre><code>1단계: n개 처리
2단계: n개 처리
3단계: n개 처리
...
총 log n 단계</code></pre>

그래서:

<code>n * log n = O(n log n)</code>

---

## <b>가장 자주 보는 경우 2: n번 반복 안에 log n 연산</b>

예를 들면 균형 잡힌 트리 자료구조를 쓸 때입니다.

- 원소 n개를 하나씩 삽입
- 삽입 1번당 O(log n)

그러면 전체는 보통 O(n log n)입니다.

예:

- set, map에 n개 삽입
- 우선순위 큐에 n번 넣기
- 원소마다 이진 탐색 1번씩 하기

예시 느낌:

<pre><code>for (int i = 0; i &lt; n; ++i)
{
    Set.insert(Arr[i]); // 보통 O(log n)
}</code></pre>

전체:

<code>n * log n = O(n log n)</code>

---

## <b>가장 자주 보는 경우 3: 분할정복</b>

패턴이 이렇습니다.

- 문제를 반으로 나눈다
- 나눈 문제를 재귀로 푼다
- 합칠 때 전체를 한 번 훑는다

이 구조가 자주 O(n log n)으로 나옵니다.

대표 예:

- 병합 정렬
- 세그먼트 트리 빌드 일부 설명에서 관련 감각 익히기
- divide and conquer 류 문제들

---

## <b>직관적으로 외우는 법</b>

- O(n): 전체를 한 번 훑음
- O(log n): 절반씩 줄임
- O(n log n): 전체를 훑는 일을 log n번 반복함

이 한 줄 감각이 제일 중요합니다.

---

## <b>실전에서 자주 보는 키워드</b>

문제에서 이런 느낌이 보이면 O(n log n)을 의심하시면 됩니다.

- 정렬을 사용함
- 각 원소마다 이진 탐색함
- 각 원소마다 set, map, priority\_queue 연산함
- 반으로 나누는 분할정복 구조임
- “브루트포스 O(n\^2)는 너무 크고, 정렬이나 로그 자료구조를 써야 한다”는 상황

---

## <b>반대로 아닌 경우</b>

이것도 같이 구분하시면 좋습니다.

- 단순 한 번 순회 -> O(n)
- 이중 반복으로 전부 비교 -> O(n\^2)
- 절반씩 줄이기만 함 -> O(log n)

즉 준선형은 보통

선형보다 느리지만, 제곱보다는 훨씬 빠른 중간급 고효율이라고 보면 됩니다.

원하시면 다음에는 제가

O(n) / O(n log n) / O(n\^2)를 구분하는 문제를 5개만 딱 내드리겠습니다.

조금 더 헷갈리는 문제 3개를 내고, 이번에는 공간복잡도도 같이 붙여서 연습하게 해줘

좋습니다. 이번에는 시간복잡도 + 공간복잡도를 같이 보게끔, 조금 헷갈리게 섞어서 3문제 드리겠습니다.

기준은 추가 공간, 즉 보조 공간복잡도로 답하시면 됩니다.

답은 예를 들어 1번: 시간 O(...), 공간 O(...) 형식으로 적어주시면 됩니다.

## <b>문제 1</b>

<pre><code>int Sum = 0;

for (int i = 0; i &lt; n; ++i)
{
    Sum += Arr[i];
}

for (int j = 1; j &lt; n; j *= 2)
{
    Sum += j;
}</code></pre>

- 시간복잡도는?
- 공간복잡도는?

## <b>문제 2</b>

<pre><code>vector&lt;int&gt; Temp;

for (int i = 0; i &lt; n; ++i)
{
    Temp.push_back(Arr[i]);
}

for (int i = 0; i &lt; n; ++i)
{
    cout &lt;&lt; Temp[i] &lt;&lt; "\n";
}</code></pre>

질문:

- 시간복잡도는?
- 공간복잡도는?

---

## <b>문제 3</b>

<pre><code>for (int i = 0; i &lt; n; ++i)
{
    for (int j = i; j &lt; n; ++j)
    {
        cout &lt;&lt; i &lt;&lt; j &lt;&lt; "\n";
    }
}</code></pre>

질문:

- 시간복잡도는?
- 공간복잡도는?

힌트는 짧게만 드리면:

- 문제 1은 더하기가 핵심입니다.
- 문제 2는 추가 배열이 생깁니다.
- 문제 3은 안쪽 반복문이 매번 n번은 아닙니다.

답 적어주시면 바로 채점하고, 왜 헷갈리기 쉬운지도 같이 설명드리겠습니다.
